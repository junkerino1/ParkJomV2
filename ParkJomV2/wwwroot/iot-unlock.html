ParkJom Bollard Test

A simple page to register a device and try the renter unlock checks.

1Optional: prepare a device ID

For your current ESP32, use the UUID shown in Serial Monitor. Generate a new ID only for a new unit. A new ID must be copied into configuredDeviceUuid in the sketch before its first boot; an ID already saved in ESP32 memory takes priority.

Registering an ID does not assign it to a parking spot. The owner must still bind the real ESP32 to the spot using the existing OTP process before a booking can unlock it.

2Connect as the renter

The token is kept only in this browser tab and is cleared when the tab closes. Use the token of the renter who owns an eligible booking.

3Unlock bollard

Press once to run the complete renter flow: GPS check, short-lived challenge, BLE proof, fresh GPS check, unlock command, then wait for the ESP32 result. The browser asks you to choose and approve the ESP32 the first time; later attempts can reconnect automatically when the browser remembers that device.

Each challenge expires after 30 seconds and can be used once. The button is disabled while an attempt is running. If the ESP32 reports a failed unlock, that challenge has already been used; pressing again starts a new challenge. If Bluetooth fails before a proof is received, you can press again to continue with the same challenge while it is still valid.

You do not type the BLE challenge text. The page sends it to the ESP32 and submits its proof to the backend automatically. Use HTTPS or localhost and a browser that supports Web Bluetooth.

Lock the bollard

This action does not ask for GPS or BLE. The API waits for the ESP32 to check three fresh HC-SR04 readings before it returns. A median reading at or below 50 cm blocks locking; too few valid readings also block it as a sensor failure.

Ready. Start by entering your renter token and booking ID.
